## 2024-03-20 - Insecure Cache Control on Savings Endpoint
**Vulnerability:** The `/api/history/savings` endpoint previously set a `Cache-Control: public` header. Because this endpoint serves sensitive, user-specific financial and energy usage statistics, this configuration could allow intermediate shared caches (such as CDNs or corporate proxies) to cache the response and potentially serve one user's data to another user requesting the same URL.
**Learning:** Shared proxy caches do not differentiate between authenticated users if the request URL is identical unless explicitly instructed. Using `public` caching directives on authenticated API responses exposes data to severe privacy leaks.
**Prevention:** Always use `Cache-Control: private` when returning user-specific data to ensure the response is only cached by the end-user's local browser and not by intermediate caches.
